# 多来源冲突处理规则

当不同来源说法不一致时，按证据强度处理，而不是按数量投票。

## 一、证据优先级

通常按以下顺序优先：

```text
1. 官方原始来源
2. 法规、监管、法院、标准原文
3. 同行评审论文或正式技术报告
4. 原始数据、代码仓库、release note、模型卡
5. 高信誉新闻机构的具名报道
6. 专业机构分析
7. 普通博客、技术社区
8. 社交平台
9. 聚合站、转载站、采集站、可疑站点
```

## 二、冲突处理规则

### 官方来源 vs 新闻报道

如果官方来源与新闻报道冲突，通常优先官方来源。新闻报道可作为补充背景。

### 新来源 vs 旧来源

如果新版官方文档与旧文档冲突，优先新版文档。

### 多个二手来源重复同一说法

多个二手来源重复同一句话，不等于独立验证。如果它们都没有原始来源，应标记为证据不足。对于中文自媒体以及一般的非权威媒体来源，即使数量众多也必须执行此规则，详见 `source_self_media.md` 中"多自媒体重复 ≠ 多方验证"。

### 跨语言信息茧房检测

当多个来源互相印证时，必须检查是否存在信息茧房回声：

```text
1. 话题信息原产地是否为另一种语言（如话题为 English-origin，但当前来源全为中文）
2. 这些来源是否全部来自同一语言生态
3. 是否有任何来源引用了原产地语言的一手来源

若满足条件 1+2 且不满足条件 3：
  → 标记 echo_chamber_detected = true
  → 不视为多方独立验证
  → 冲突状态标记为 evidence_insufficient
  → 必须注明"仅在单一语言生态内重复，未找到原产地语言一手来源"
```

此项检测依赖 `rules/05_cross_region_verification.md` 中确定的话题原产地语言判定结果。

### 学术来源冲突

如果论文结论冲突，应区分：

```text
实验条件
样本大小
是否同行评审
是否有复现
是否为综述或单篇研究
```

### 法律政策冲突

必须优先官方有效文本，检查：

```text
司法辖区
生效日期
修订状态
是否只是草案、征求意见稿或媒体解读
```

## 三、输出标签

```text
resolved_by_primary_source
resolved_by_newer_source
conflicting_evidence
evidence_insufficient
secondary_sources_only
```

## 四、推荐输出

```json
{
  "conflict_status": "conflicting_evidence",
  "summary": "官方文档尚未说明该功能已开放，但多家媒体报道称正在测试。",
  "preferred_source": "official documentation",
  "final_note": "目前只能确认该功能处于测试或报道阶段，不能确认已全面开放。"
}
```
