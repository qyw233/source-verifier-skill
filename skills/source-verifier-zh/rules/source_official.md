# 官方来源处理规则

官方来源通常可靠性较高，但仍然需要检查其信息的时效性和具体语境。

## 强官方来源

```text
公司官方网站
政府机构通知
官方文档
官方 API reference
官方 GitHub 仓库
release note
changelog
标准组织文件
官方模型卡
官方许可证文件
```
## 可能的弱官方来源

```text
官方博客（可能包含营销内容）
官方社交媒体账号（可能存在宣传性质）
官方论坛（可能包含用户生成内容）
```

## 检查步骤

1. 确认域名或账号确实属于原始组织，而非仿冒钓鱼网站或二手转载，可以运用工具检查 SSL 证书、WHOIS 信息、社交媒体认证等。
2. **确认页面内容是官方团队发布还是平台用户投稿。** 域名属于官方组织不代表页面内容具备官方权威——很多公司/机构运营开放投稿的开发者社区、博客平台或论坛，用户可自行发布内容。必须检查：
   - 作者身份：是官方团队实名署名还是用户昵称/匿名？作者栏是否有“官方团队”“平台管理员”等标识？
   - URL 路径：是 /docs/、/api/、/release-notes/ 等官方维护路径，还是 /article/、/blog/、/community/、/user/ 等开放投稿路径？
   - 发布机制：页面是否有“投稿”“作者个人观点，不代表平台立场”“用户发布”“社区贡献”等声明？
   - 若判定为平台上的 UGC 内容（用户生成内容），即使域名属于官方，也应**终止 source_official 规则，重新路由到 blog_forum 或 self_media 规则进行评估**。
3. 检查页面是否为当前版本，而不是归档页或旧版本文档。
4. 区分页面性质：
   - 文档
   - release note
   - 技术报告
   - 营销页面
   - 博客公告
   - 法律条款
   - 产品介绍
   - 其他
5. 对功能、API、许可证、开源状态，优先使用：
   - 文档
   - release note
   - changelog
   - GitHub 仓库
   - 模型卡
   - LICENSE 文件
6. 对性能、效果、领先性等评估时，需注意官方宣传性质。

## 特殊规则

### 开源状态评估

要确认为“开源”，应当在官方渠道中找到以下之一：

```text
公开代码仓库链接
公开模型权重页面链接
LICENSE 文件
官方发布页明确指向代码或权重
包管理器或模型平台的官方条目
```

### 功能支持评估

优先参考：

```text
官方文档
API reference
SDK changelog
release note
示例代码
```

### 产品可用性评估

需要检查：

```text
是否所有用户可用
是否仅限 beta
是否仅限特定地区
是否仅限企业版
是否需要申请权限
```

## 风险提示

官方来源可以代表“官方声称了什么”，但对于以下内容仍需保持批判性：

```text
性能优于所有竞品（可能存在选择性评测）
用户体验评估
市场占有率数据
安全性绝对保证
医学或法律效果描述
```

这些通常需要独立评测、监管文件、同行评审或第三方数据支持。
