# 博客、论坛和社区来源处理规则

博客和论坛的质量差异极大，需要首先区分来源形态，再结合作者身份、内容类型与可核验性综合判断。

## 一、首先区分博客与论坛

在评估之前必须先确定来源是博客还是论坛，两者的证据性质和评估维度不同：

### 博客特征

```text
以作者个人或团队为核心，围绕特定主题发布文章
内容通常为长文，作者对内容有完整控制权
页面通常有明确的作者介绍、发布日期
读者互动以评论区形式存在，不影响正文
常见平台：独立博客、Medium、CSDN 博客、知乎专栏、微信公众号、掘金
```

### 论坛特征

```text
以话题或帖子为基本单元，多方参与讨论
内容由楼主发帖 + 回帖构成，信息分散在多个回答中
作者身份可能多样（楼主、回帖者、路过网友）
答案或结论可能不在首帖，需要遍历回帖
常见平台：Stack Overflow、GitHub Issue、V2EX、Reddit、百度贴吧、NGA、知乎问答
```

### 判定后分流

```text
判定为博客 → 跳至"第三章：博客"
判定为论坛 → 跳至"第二章：论坛"
```

## 二、论坛

论坛的核心特征是多人参与讨论，因此评估重点不是单一作者，而是**讨论内容和结论的可信度**。

### 2.1 首先判断论坛讨论类型

拿到一个论坛来源后，先判断属于哪种讨论类型：

```text
技术/问题解决类： 提问-解答模式，有明确的问题和预期答案
                 例：Stack Overflow 问答、GitHub Issue、V2EX 技术求助、CSDN 问答

观点讨论类：      各抒己见，没有标准答案，讨论主观感受或价值判断
                 例：Reddit 热帖、贴吧讨论帖、知乎"如何看待"类问题

产品/事物讨论类： 围绕某个具体产品、服务、品牌进行讨论
                 例：贴吧产品评测帖、NGA 硬件讨论、小红书种草帖
```

### 2.2 技术/问题解决类论坛

此类论坛可信度取决于**问题是否得到解决**以及**解决方案是否可复现**。

#### 检查步骤

```text
1. 问题是否有明确答案或解决标记（如 Stack Overflow 的 Accepted Answer、GitHub Issue 的 Closed 状态）
2. 解决方案是否包含可复现步骤（代码、命令、配置）
3. 回答者身份是否可查证（维护者、项目成员、高信誉用户）
4. 解决方案是否适用于当前版本（检查时间戳）
5. 是否有多个独立回答者给出相似方案
```

#### 可信度分级

```text
有官方Accepted/Closed标记 + 含代码 + 多人验证 → 可信度较高，citation_usability 可达 usable
有解决方案但未被标记 + 仅单一回答 → 可信度中等，citation_usability: use_with_caution
问题已提出但无有效回答 → 仅作为线索，citation_usability: not_recommended
只有猜测性回答、无代码、无验证 → 可信度低，citation_usability: not_recommended
```

### 2.3 观点讨论类论坛

在贴吧、Reddit、知乎"如何看待"等各抒己见的场景中，论坛内容本身不能作为事实证据，只能反映**某些人群的观点分布**。

```text
可参考内容：公共反应、用户情绪、经验分享的多样性
不可作为：事实确认、数据来源、官方立场、科学结论
默认 citation_usability: use_with_caution 或 not_recommended
```

如果讨论中有引用原始来源（官方公告、论文、法规），应以原始来源为准，论坛内容仅作补充。

### 2.4 产品/事物讨论类 — 疑似广告检测

当论坛讨论围绕某个**具体产品、品牌、服务、课程、APP**时，必须检测是否存在隐形广告或软文。

#### 疑似广告信号

```text
发帖者或高赞回答者的账号为新注册或仅发布过同类内容
内容大篇幅赞美，几乎没有缺点或风险描述
包含推广链接、优惠码、邀请码、"私信我"等引流行为
多楼层内容高度雷同，回复时间集中
内容使用明显的营销话术（"亲测有效""必须入手""绝了""yyds"）
发帖者跨多个平台发布相似内容
账号头像或签名带有商业信息
```

#### 处理方式

```text
确认或高度疑似广告 → 添加次级标签 suspected_advertisement
                    → citation_usability: not_recommended 或 do_not_use
                    → warnings 中注明"疑似商业推广内容"
                    → 建议寻找中立评测或官方信息

不能确定是否广告但存在个别信号 → 添加次级标签 possible_advertisement
                                → citation_usability: use_with_caution
```

## 三、博客

博客以作者为核心，评估重点在于**作者身份与内容质量**。

### 3.1 技术类博客

技术类博客指围绕软件开发、AI、工程、运维等技术话题的个人或团队博客。

#### 高质量技术博客信号

```text
作者身份清晰，可查证其技术背景（如 GitHub 主页、LinkedIn、个人项目）
文章包含可运行的代码、日志、配置或复现步骤
链接到官方文档、论文、GitHub issue 或源码
标注写作日期和更新记录
结论有边界，明确适用范围和限制条件
存在有价值的读者讨论或作者跟进回复
历史文章质量一致，无频繁翻车记录
```

#### 低质量技术博客信号

```text
作者匿名或不可查证
只给结论不给方法，无代码无步骤
过度 SEO 化、关键词堆砌
内容明显复制或翻译他人文章，或者ai生成内容
标题夸张（"一文搞懂""全网最全"），正文浅薄
广告或课程推广占比较大
把特定环境下的个例推广为通用结论
```

#### 可信度参考

```text
知名项目维护者/核心贡献者的技术博客 → 可信度较高
有实名+可查证背景+引用原始来源 → 可信度中等偏上
匿名+无引用+无代码 → 只能作为线索
```

### 3.2 非技术类博客

非技术类博客的可信度高度依赖**作者身份与用户提问的关系**。

#### 核心判断：作者是谁？

如果用户提问涉及"某人是否说过某句话"或"某人的观点是什么"：

```text
博客作者就是用户所问的那个人：
  → 该博客对该人的观点具有最高证据效力（一手来源）
  → source_type 可升级为 official，并加标签 primary_source
  → citation_usability: highly_usable

博客作者是第三方，引述或评论了那个人的话：
  → 只能代表博客作者的理解，不能等同于被引述者的原意
  → 应尽量查找被引述者的原始发言
  → 如果找不到原始来源，需标注"引用链不完整"
  → citation_usability: use_with_caution 或 not_recommended
```

#### 个人观点类博客

```text
博客仅表达作者个人观点、评论、感想 → 不代表事实
若作者是领域专家（可查证资质），观点有一定参考价值
若作者身份不明，该观点不能作为论证依据
必须标注"该内容为个人观点，未经独立验证"
```

### 3.3 博客质量通用检查

无论技术还是非技术博客，都应检查：

```text
是否有明确作者？         → 无作者扣分
是否有发布日期？         → 无日期扣分
是否有原始来源链接？     → 未引用扣分
是否有商业推广未标注？   → 未标注则加 suspected_advertisement
内容是否与标题一致？     → 不一致扣分
是否区分事实与观点？     → 未区分则降低 article_quality_score
```

## 四、适合与不适合使用的场景

### 适合作为参考

```text
软件排错、环境配置、开发经验
技术教程、实现示例
用户体验真实反馈（需标注为个人体验）
技术趋势的个人观察（需标注为个人观点）
当事人本人的公开表达（博客为作者本人时）
```

### 不适合作为最终证据

```text
法律政策依据
医学诊断或治疗建议
金融投资建议
科学共识的唯一来源
公司官方发布状态的唯一确认
开源许可证判断
重大新闻事件的唯一报道
```

## 五、输出建议

```json
{
  "source_type": "blog_forum",
  "content_form": "blog | forum",
  "author_expertise": "clear | unclear | unknown",
  "forum_subtype": "tech_qa | general_discussion | product_discussion",
  "problem_resolved": true,
  "solution_has_code_or_steps": true,
  "advertisement_suspected": false,
  "evidence_type": ["code", "logs", "screenshots", "personal_experience", "opinion_only"],
  "citation_usability": "usable | use_with_caution | not_recommended | do_not_use",
  "reasons": ["..."],
  "warnings": [
    "该来源为论坛讨论，缺乏权威审核",
    "问题尚未有明确解决方案",
    "疑似商业推广内容"
  ]
}
```

### 新增字段说明

| 字段 | 说明 |
|------|------|
| `content_form` | `blog` 或 `forum` |
| `forum_subtype` | 论坛子类型：`tech_qa`（技术问答）、`general_discussion`（一般讨论）、`product_discussion`（产品讨论） |
| `problem_resolved` | 仅论坛技术问答有效：问题是否已解决 |
| `solution_has_code_or_steps` | 解决方案是否包含可行步骤 |
| `advertisement_suspected` | 是否疑似广告 |
