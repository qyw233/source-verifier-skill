# 跨区域 / 跨语言溯源验证规则

本规则在流程最早期执行——拿到用户提问后，先判断信息原产地语言，设定跨语言评估基线。

## 一、核心原则

1. **信息原产地原则**：话题的信息一手来源通常在话题发生地的语言环境中。美国公司 → 英文官方；中国政策 → 中文官方；日本产品 → 日文官方。
2. **语言错配降权原则**：非原产地语言报道同一话题，除非引用了原产地语言的一手来源，否则自动降权。
3. **中文自媒体和一般媒体生态警告**：中文信息生态中存在大量洗稿/搬运型内容农场，不能仅凭"多个中文来源说法一致"视为多方独立验证。

## 二、话题原产地判定

从用户提问中分析信息源头应在哪个语言/区域：

### 判定维度

| 维度 | English-origin | Chinese-origin | Other |
|------|---------------|----------------|-------|
| 公司/产品 | 美/英/加/澳等英语国家公司 | 中国公司/产品 | 日/韩/欧等 |
| 政策/法规 | FDA, EU AI Act, SEC等 | 中国政策、法规 | 当地法规 |
| 学术/技术 | 主要国际期刊、会议 | 中国学术机构主导 | 当地机构 |
| 事件 | 发生在美国/英国等的事件 | 发生在中国的事件 | 当地事件 |

### 判定方法

```text
1. 从用户提问中提取关键实体（公司名、产品名、法规名、人物、机构）
2. 判断这些实体的归属国家/区域
3. 确定信息原产地语言：
   - 美国/英国/加拿大/澳大利亚/国际通用 → 英文（English-origin）
   - 中国 → 中文（Chinese-origin）
   - 日本 → 日文
   - 其他 → 当地语言
4. 如无法确定 → 标记为 unknown，不做跨语言降权
```

### 示例

```text
用户问："OpenAI 最新发布的 GPT-5 支持哪些功能？"
  → 实体：OpenAI（美国公司）、GPT-5（美国产品）
  → 信息原产地语言：English-origin

用户问："欧盟 AI Act 对基础模型有哪些要求？"
  → 实体：EU AI Act（欧盟法规）
  → 信息原产地语言：English-origin（欧盟官方文本以英文为主）

用户问："百度文心一言最新版本有什么更新？"
  → 实体：百度（中国公司）、文心一言（中国产品）
  → 信息原产地语言：Chinese-origin
```

## 三、来源语言与话题原产地匹配规则

### 3.1 直接匹配（来源语言 = 话题原产地语言）

正常评估，不加跨语言降权。

### 3.2 语言错配（来源语言 ≠ 话题原产地语言）

如果某个来源以非原产地语言报道（如中文文章报道美国公司产品），按以下规则处理：

#### 有原始来源引用
如果该来源**明确引用并链接**了原产地语言的一手来源（官方公告、论文、法规原文等）：
```text
- 添加次级标签：cross_language_report
- 正常评估，不额外降权
- 在 reasons 中注明"已引用原始语言一手来源"
```

#### 无原始来源引用
如果该来源**未引用**原产地语言的一手来源：
```text
- 添加次级标签：cross_language_report
- source_reliability_score 额外 -15
- citation_usability 至少降低一档（usable → use_with_caution → not_recommended → do_not_use）
- 在 warnings 中注明："该来源以非原产地语言报道，且未引用原始语言一手来源"
```

## 四、语言生态基线信誉调整

不同语言的信息生态在结构性上存在差异。以下调整在评估**非原产地语言来源**时叠加。

### 4.1 英文来源（对 Chinese-origin 话题）

```text
- 英文主流新闻/学术来源：有较完善的编辑审核机制，通常可信度较高 → 正常评估
- 英文自媒体/博客/论坛：与中文同类来源同等对待，不作特殊加分
- 英文小报/tabloid/内容农场：按 suspicious 处理
```

### 4.2 中文来源（对 English-origin 或其他非中文话题）

中文信息生态中，非官方来源（自媒体、一般媒体、博客论坛）存在结构性可信度风险：

```text
- 大量洗稿/搬运型自媒体互相抄袭，形成虚假的"多方印证"
- 营销号以流量为首要目标，内容准确性无保障
- 部分平台（如百家号、头条号等）内容审核侧重于合规而非事实准确性

调整规则（仅对非中文原产地话题生效）：
- 中文 self_media：额外 -10（叠加在 source_self_media.md 的已有评分上）
- 中文 blog_forum（非 Stack Overflow、GitHub 等国际平台）：额外 -8
- 中文 news（未具名记者或未链接原始来源）：额外 -5
- 中文官方媒体/官方来源：正常评估，不加额外罚分
```

注意：以上降权是针对**非中文原产地话题**的额外调整。如果话题本身是 Chinese-origin（如中国公司产品、中国政策），中文来源不适用此降权规则。

### 4.3 中文低质内容平台识别

以下平台在中国信息生态中以低质内容为主，在评估时应默认带有负面预设（除非该页面引用了可验证的原始一手来源）：

```text
- 百度百家号（baijiahao.baidu.com）：内容农场，大量洗稿和 SEO 垃圾
- 搜狐号（mp.sohu.com, sohu.com/a/...）：内容搬运平台
- 网易号（dy.163.com, 163.com/dy/...）：内容分发平台
- 头条号（toutiao.com 上的自媒体文章）：流量驱动内容
- 其他内容分发平台：大鱼号、企鹅号、一点号、大风号等

识别特征：
- URL 路径包含 /a/、/dy/、/mp/ 等平台内容分发路径
- 页面有明显"xx号""xx创作者"等平台自媒体标识
- 文章标题夸张、正文浅薄、无作者实名或作者不可查证
- 页面存在大量推荐链接或广告

处理：
- 来自这些平台的文章，归类为 self_media 或 aggregator_or_scraper
- 除非文章明确引用并链接了可验证的原始一手来源，否则 citation_usability 不超过 use_with_caution
- 在 warnings 中注明来源平台低质风险
```

## 五、信息茧房回声检测

当处理多个来源时，应检查是否存在以下模式：

### 检测条件
```text
1. 话题为 English-origin 或其他非中文原产地
2. 当前所有可用来源均为中文
3. 这些中文来源之间内容相似但没有引用统一的原始来源
4. 未找到任何原产地语言的一手或权威来源
```

### 判定
```text
如果全部满足 → echo_chamber_detected = true
  → 不视为多方独立验证
  → 即使来源数量多，也不能提高整体可信度
  → 在冲突解决报告中标注 echo_chamber_risk
  → 建议：搜索原产地语言来源后再评估
```

## 六、输出格式

### 全局评估（单次评估的所有来源共用）

```json
{
  "topic_origin_language": "english | chinese | japanese | other | mixed | unknown",
  "topic_origin_region": "US | CN | JP | EU | ...",
  "echo_chamber_detected": false,
  "origin_language_sources_found": true,
  "cross_language_notes": "该话题信息源头应在英文环境，当前中文来源均未引用英文一手来源，需降权处理"
}
```

### 每个来源追加的判定

```json
{
  "cross_language_report": true,
  "language_matched_with_origin": false,
  "cites_primary_source_in_origin_language": false,
  "cross_language_penalty": -15
}
```

## 七、与其他规则的协作

- 本规则在流程**第 1.5 步**执行，在 URL 标准化之后、来源类型分类之前
- 本规则的输出影响后续 `01_general_scoring.md` 中的评分加减
- 本规则的信息茧房检测结果供 `04_conflict_resolution.md` 使用
- 本规则对中文低质平台的识别结果影响 `00_source_taxonomy.md` 中的类型判定
